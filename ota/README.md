# CallOnFail current version

The ESP32 reads `manifest.json` from this directory over Ethernet.

Expected production files:

- `manifest.json`: firmware, audio and runtime configuration metadata.
- `firmware.bin`: PlatformIO build output copied from `.pio/build/wt32-eth01/firmware.bin`.
- `audio/cof_fallback.wav`: 8 kHz, 16-bit, mono WAV. Uploaded to the A7672 modem
  as `C:/cof_fallback.wav` and played by an **alarm** call when the device cannot
  download the server TTS (site with no Ethernet/WiFi). Regenerated by hand: bump
  `audio.version` and the `sha256` when it changes.
- `audio/cof_test.wav`: the historical lab test audio. No longer what an alarm
  call plays; kept as the canonical bench asset.

`manifest.json` advertises one audio asset at a time, so the file above is the
current one. `release-fw.py` only rewrites `firmware.*`; it leaves the `audio`
block alone.

Keep the firmware version in `manifest.json` higher than the version compiled in
`include/cof_config.h` when you want deployed devices to update OTA.
